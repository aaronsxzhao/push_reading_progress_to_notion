# 微信读书自动摘录 · Obsidian 插件

版本 0.1.2。免费、保留 iCloud，同时面向 macOS 和 iPhone/iPad。最低 Obsidian 版本为 **1.11.4**，用于调用本设备的 SecretStorage。

0.1.1 修复：点击立即同步后马上显示开始提示；按钮显示“同步中”，设置页和结果弹窗实时显示进度。独立设置窗口使用自身的前台状态，避免主窗口不可见时静默忽略手动同步。

0.1.2 更新：固定使用 WeRead Book ID 识别同一本书；历史不同标题来源自动读取、合并重复摘录，不再弹出来源选择。

这是可手动安装的本地版本，尚未发布到 Obsidian 社区插件商店。

## 行为

- 打开笔记库或 App 回到前台时检查 Notion；没有周期轮询。启动和焦点事件在 5 秒内合并。
- Mac、iPhone 都直接通过 Notion API 读取内容；手机导入不需要 Mac 开机。
- 数据链路是微信读书 → 现有 GitHub 任务 → Notion → 当前打开的 Obsidian → iCloud。
- 每本书一个 `【自动摘录】书名--来源ID.md`。ID 后缀用于避免重名；文件内标题仍为书名。
- 只导入 `Source` 字段**仅包含** `WeRead` 的书籍，不导入纸质书或来源不明确的记录。
- 完整读取所有分页和子块，保留章节、划线、想法及对应原文、书评。无正文的新书不创建空文件。
- 有变化才更新；正文减少时也跟随 Notion 更新。整本书查不到、无权限或网络失败时不删除本地文件。
- 本轮逐书完成；中断时已经成功的书保留，未完成的书下次重新读取。

## 个人笔记与去重保护

- 仅更新当前同步目录中带有本插件所有权标识且来源吻合的文件。普通手写笔记、其他目录内文件不接管。
- 即使同名文件已经存在，也不覆盖；会在同步结果中提示。
- 若自动摘录正文被手动编辑，内容校验会阻止覆盖。请将自己的笔记另建文件。
- 书名变化只更新原文件正文，不另建文件；优先使用 Notion 的 `WeRead Book ID`，兼容官方封面中的历史 ID；没有可靠微信 ID 时退回 Notion 页面 ID。
- 同一书籍 ID 的多个 Notion 页面全部读取成功后，自动合并成一份摘录；相同内容块只保留一份，不同内容都保留。任何来源读取失败则保留本地旧文件，不弹出书名选择。不同 ID 不凭相似标题合并。
- 发现多个本地摘录副本时暂停该书，不擅自删除副本。
- 单设备不会并行执行多个同步任务。写入使用 Obsidian Vault.process，在提交时再次检查文件是否发生变化。

## 安装到 Mac

1. 确认 Obsidian ≥ 1.11.4，打开你原来的 iCloud 笔记库。
2. 下载并解压安装包，得到 `weread-notion-excerpts` 文件夹，里面有 `main.js`、`manifest.json`、`styles.css`。
3. 将整个文件夹放到：`你的笔记库/.obsidian/plugins/weread-notion-excerpts/`。如果不存在 `plugins`，新建它。Finder 中按 `⌘⇧.` 显示隐藏文件夹。
4. 重启 Obsidian。在「设置 → 第三方插件 / Community plugins」中启用「微信读书自动摘录」。如果笔记库处于限制模式，需要由你确认允许第三方插件。
5. 打开「设置 → 微信读书自动摘录」，按下一节配置。

不要直接把安装包当成一个新笔记库。也不要把整个开发目录复制进去，运行只需要上面三个文件。

## 配置 Notion 只读连接（首次一次）

建议创建独立的只读连接，不修改现有 GitHub 自动同步使用的连接。

1. 在 Notion Developer portal 的 **Internal connections** 创建连接，例如 `Obsidian 读书摘录`，选择你的工作区。
2. 在 Configuration / Capabilities 中仅保留 **Read content**，关闭 Update content、Insert content、评论写入等权限。不需要用户信息。
3. 在 Content access 中仅授权你的读书数据库；也可以在该数据库右上角 `••• → Connections → Add connection` 中添加这个连接。子页面会继承访问权限。
4. 复制这个连接的 API token，粘贴到插件的「Notion 只读凭据（本设备）」，点击「保存凭据」。不要放在 Markdown 或发送到公开仓库。
5. 复制读书数据库的链接，填写到「Notion 数据源 ID 或数据库链接」。链接需指向原数据库，而非包着它的普通父页面。如果数据库有多个数据源，请填写目标数据源 ID。
6. 默认输出目录为 `微信读书自动摘录`，也可填 `阅读/微信读书自动摘录`。
7. **第一台设备**点击「连接并创建空目录」，然后「立即同步」。首次可能需要几分钟，取决于书籍和嵌套想法数量，请保持 App 在前台。

凭据通过 Obsidian SecretStorage 保存到本设备，不保存在插件 data.json 或摘录文件中。后续在其他设备上分别保存一次凭据。任何同一 Obsidian 实例内运行的插件都可能拥有较广权限；不要把 SecretStorage 理解为不同插件之间的安全隔离。

## 在 iPhone 上启用

1. 更新 iPhone Obsidian 到 ≥ 1.11.4，打开**同一个 iCloud 笔记库**。
2. 等待 Mac 上放入的 `.obsidian/plugins/weread-notion-excerpts/`、插件设置和摘录目录通过 iCloud 到达。必要时退出并重新打开 Obsidian。
3. 在「设置 → 第三方插件」确认插件可见并启用。若两端配置的设置文件夹不同，需要把三个插件文件也安装到手机使用的那个配置文件夹中；默认两端都是 `.obsidian`。
4. 在插件设置中保存同一个 Notion 只读 token。数据源和目录配置通常随 iCloud 到达；若没有，请填写相同数据库链接。
5. 使用「**识别已有目录**」，不要再次初始化新目录。然后点击「立即同步」。
6. 以后打开/返回 App 就会检查。手机锁屏或切到后台时不能保证持续运行；插件会在下次打开重新核对。

若手机暂时看不到插件或标识文件，请先等待 iCloud 同步，不要用“创建目录”来解决等待问题。

## 移动目录

可以把整个 `微信读书自动摘录` 文件夹移动到**同一笔记库内**任何普通目录，例如从根目录移动到 `阅读/微信读书自动摘录`。

- 保留里面的 `_微信读书同步标识.md`，它不包含密钥。
- 插件在笔记库内查找这个标识，移动后自动找到新位置。
- 找不到标识时暂停，不在旧路径重建目录。
- 同一个标识有多份时，弹窗显示完整路径让你选择；不会删除其他副本。
- 不能通过这个机制跨两个不同的 Obsidian 笔记库追踪文件。

## 日常使用与故障处理

- 立即检查：点击侧边栏同步图标，或命令面板「微信读书自动摘录：立即同步 Notion 摘录」。
- 查看错误：命令面板「微信读书自动摘录：查看同步结果」或插件设置中的「查看结果」。
- 没变化时自动检查不弹通知；发生更新或需要处理时会提示。
- 停止：插件设置里的「停止本次同步」，或禁用插件。已生成 Markdown 仍可阅读。
- 同一本书存在多个历史来源：按固定 ID 自动合并，不再需要选择；旧版保存的来源选择不再生效。
- 偶尔需要等待：Notion 限流时按服务端要求短暂退避；长时间限流、无权限或超时则暂停，不把失败解释成空笔记。

## 已知边界

1. 保留简化架构，没有引入服务器锁。GitHub 上游同步同样按固定 ID 更新 Notion，旧标题的空重复记录经检查后移入回收站；含独有正文或个人字段的历史页保留并报告。插件尽量通过读前/读后时间戳检查识别正在更新的页面，但无法获得 Notion 的全库原子快照；恰好碰上上游写入可能读到中间状态，下次打开再核对。
2. iCloud 本身不是跨设备的即时锁。两台设备在各自尚未收到另一端文件时同时首次导入，iCloud 仍可能产生冲突副本；插件检测到重复后会停止，不声称绝对消除 iCloud 冲突。首次请先在 Mac 完成导入，再等手机收到目录后启用。
3. 不做双向写回。Obsidian 内容不会写回 Notion 或微信读书；个人手写笔记不参与同步。
4. Notion 没有保留的原始微信读书字段不推测补齐。不读取 Notion 讨论区评论；微信读书“想法/书评”来自现有页面正文。
5. 暂不支持的 Notion 块会暂停该书并保留原文件；Notion 私有附件只提供原页面入口，避免生成会失效的临时链接。

## 开发

不需要 npm install；没有第三方运行依赖。

```sh
npm run check
```

`src/core.js` 是数据读取与文件保护逻辑，`src/main.js` 是 Obsidian 交互层。构建脚本将两者打成单个 `main.js`，运行时只引用 Obsidian 自带 API。
